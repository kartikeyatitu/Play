## 1. Headline diagnosis

The app is really **three design languages layered on each other**:

1. **New shell language.** Calm Linear/Stripe style: semantic tokens (`bg-surface`, `text-ink-muted`, `border-line`), `rounded-xl`, Geist, sentence case, 200 ms fades. It covers `dashboard-shell`, `shell/*` (Today, KpiTile, EmptyState, SectionHeader), login, coach header and Team/Payroll.
2. **Legacy "athletic" language.** Uses `zinc-*`/`lime-*` aliases, `rounded-3xl` + `shadow-xl` cards, `font-black uppercase tracking-wider` 10–11 px labels, emoji status, pulsing dots and gradient text. It covers `ui/card.tsx`, `ui/badge.tsx`, `ui/StatusChip.tsx`, `ui/input.tsx`, all of `parent/*`, most of `org/*` feature panels, `SessionAttendanceCard`, onboarding, `/join` and the receipt page.
3. **Marketing language.** Hard-coded lime glow, white dot-grid, float/ping/marquee animations and a lime→emerald gradient headline (`components/marketing/*`, `marketing.css`). It never moved to the orange light theme.

The token system itself is well thought out. The light/dark ramps are documented with contrast notes, there's a boot script to avoid flash, and print overrides exist. The weak point is that the old Tailwind names were *remapped* (`zinc` = neutral ramp, `lime` = orange accent, `white` = "ink-inverse"). Because of that, 3,397 `zinc-*` usages and 534 out-of-ramp status shades still compile but mean different things per theme. And 300+ uses of Tailwind colours that were never themed (purple, cyan, indigo, red, blue) fail contrast in the default light theme.

Numbers from the greps:

## 2. P0: fix first (correctness, contrast, trust)

**P0-1. Untheme colours are unreadable in the default (light) theme.** `purple-300` on white is 1.77:1, `cyan-400` 1.81, `cyan-300` 1.45, `blue-400` 2.54, `red-400` 2.77, `violet-400` 2.72, `indigo-400` 2.98. These colours were picked for the old black UI.
- Worst places: `src/components/coach/SessionAttendanceCard.tsx` (lines ~412 `text-purple-300` header, ~659 `bg-purple-500 text-zinc-950` button), `src/app/join/JoinForm.tsx:41` (`text-red-400` error on the public parent sign-up), `src/components/ui/badge.tsx` (`purple` variant), and the cyan/indigo uses across `org/*` analytics panels.
- Fix: add `violet`/`info` ramps to `themes.css` (or map to `sky`/`accent-2`) and lint-ban raw palettes (see §5).

**P0-2. Grey text below AA.** Measured from `themes.css`:
- `text-zinc-600` is 3.06:1 on white (light) and 2.74:1 on surface (dark): 78 uses.
- `text-zinc-700` is **1.54:1** (light) and 1.71:1 (dark), which is effectively invisible: 13 uses.
- `text-zinc-800` is worse still: 4 uses.
- Files include `parent/CheckoutModal.tsx:162`, `parent/CoachDirectory.tsx:81`, `parent/GamificationWidget.tsx:44`, `parent/AchievementBadges.tsx:64`, `ui/empty-state.tsx`, `org/AdminClient.tsx` (batch card "Capacity: —"), `shell/AttentionItem.tsx`, `shell/MoreScreen.tsx`, `directory/*`.
- Also: `text-zinc-500` on `surface-2` in dark is 4.45 (just fails), and the login placeholder `text-ink-subtle/70` is about 3.3:1.
- Fix: replace with `text-ink-subtle` (5.0+) everywhere and forbid 600+ for text.

**P0-3. Public `/join` form (parents' first touch) is the least finished screen.** `src/app/join/JoinForm.tsx`:
- placeholders are used as labels ("Parent Name", "Parent Phone Number" in Title Case, with no `<label>`);
- no `autoComplete` (`name`, `tel-national`);
- no `inputMode`;
- a native `<select>` styled `p-2` (about 36 px) with no label;
- the error uses red-400 (2.77:1 in light);
- `bg-zinc-950` overrides make the inputs off-white on an off-white page.

Copy the pattern from `components/directory/form-fields.tsx` / `trial-request-form.tsx`, which already have labels and autocomplete.

**P0-4. Login can show a dangling "or with email" divider in production.**
- In `src/app/login/page.tsx` ~195–223, when `googleClientId` is unset and `NODE_ENV==="production"`, the Google block renders `null` but the divider still renders. When it is set in dev, the button reads "Continue with Google (Mock Mode)". That label also appears in `/home/claude/shots/design/after-login-phone.png`, so make sure no preview deploy ships it.
- Also add `autoComplete="email" | "current-password" | "new-password" | "tel"` to the inputs at lines 231–255. Only OTP has one, and password managers and Android autofill depend on these.
- The Sign In / Register segmented control is `h-9` (36 px) and has no `role="tablist"`/`aria-selected`.

**P0-5. Money formatting is inconsistent and sometimes wrong.**
- There are two `formatINR`s with different contracts. `src/lib/pricing.ts:88` adds `₹` and uses `en-IN`; `src/lib/directory.ts:159` has no symbol.
- 32 `toLocaleString()` calls with no locale render `₹100,000` vs `₹1,00,000` depending on the device, and can cause hydration mismatches between server (en-US) and client (en-IN). Files: `parent/FamilyDashboard.tsx` (6), `org/RevenueForecast.tsx`, `org/RevenueProjection.tsx`, `org/FeePricingAnalyzer.tsx`, `org/FeePlans.tsx`, `org/AnalyticsDashboard.tsx:165`, `app/r/[token]/page.tsx:160,167` (**the receipt**), `app/c/[coachId]/page.tsx:225`, `directory/academy-card.tsx:105`.
- Some amounts aren't formatted at all: `parent/FeeHistory.tsx:61` `₹{record.amount}` and `parent/CheckoutModal.tsx:90,98,106,142` ("Pay ₹2500 in UPI app").
- Fix: one `formatMoney(amount, {compact?})` and one `formatDate(d, "short"|"long"|"weekday")` in `src/lib/format.ts`, both hard-wired to `en-IN` + `Asia/Kolkata`. Ban bare `toLocale*` with lint.

**P0-6. Native `alert()`/`confirm()` for destructive and money actions** (46 calls). This includes `org/PendingPayments.tsx` (confirm payment), `org/PayrollPanel.tsx`, `org/StoreOrdersPanel.tsx` (5), `org/TeamPanel.tsx`, `org/StudentDetailDrawer.tsx`, `org/AdminClient.tsx` (3) and `parent/ProShop.tsx`.
- On Capacitor/Android WebView these dialogs show the page URL as the title and break the theme.
- Fix: wire up the existing unused `src/components/ui/confirm-dialog.tsx` (or a `useConfirm()` hook) and use toasts for the `alert` cases.

**P0-7. Bad pluralisation and emoji status in parent money UI.**
- `parent/FamilyDashboard.tsx:71` renders "1 Children Enrolled".
- Lines 132/180/182 encode fee state as `✅`/`⚠️` plus "PAID ✅ / PENDING ⚠️".
- `parent/CoachDirectory.tsx:88` shows coach verification as a run of ✅/⏳ emoji.
- Emoji render differently per OS and are read aloud oddly by screen readers. Use `PaidBadge` (`ui/status-mark.tsx`) and a status chip.

## 3. P1: consistency, mobile and accessibility

**P1-1. The base primitives are still legacy, so every new screen inherits the old look.**
- `ui/card.tsx`: `rounded-3xl … bg-zinc-900/70 shadow-xl`, and `CardTitle` is `font-black text-white`.
- `ui/badge.tsx`: `text-[10px] font-black uppercase tracking-wider`.
- `ui/StatusChip.tsx`: an `animate-pulse` dot that pulses forever on *every* chip, including "Paid" and "Cancelled".
- `ui/input.tsx`: `rounded-xl border-zinc-800 bg-zinc-900/90 … focus-visible:border-lime-400`.
- `ui/button.tsx` (shadcn) defaults to `h-8`, `sm` = `h-7`, `xs` = `h-6`, `icon` = `size-8`. It is used in 86 files, so most buttons in feature panels are 28–32 px tall on phones.
- Fix: restyle these five files to the shell language. Card becomes `rounded-xl border-line bg-surface shadow-hairline`. CardTitle becomes `text-base font-semibold text-ink`. Badge becomes sentence case 12 px medium with no pulse. Button default becomes `h-10 sm:h-9` with `min-h-11` on coarse pointers (`@media (pointer:coarse)`). This one change fixes the look of ~100 files.

**P1-2. Two bottom-nav implementations and three headers.**
- `ui/dashboard-shell.tsx`: admin/parent, 56 px tall, 10 px labels, accent bar `inset-x-5`.
- `coach/CoachTabs.tsx`: 64 px tall, 11 px labels, `w-10` bar, a badge, and stroke-width switching.
- The parent portal still uses the "legacy ungrouped" path, with a hamburger + drawer **and** a 4+More bottom bar (`dashboard-shell.tsx:150-244`), so parents get two navigation systems at once.
- Fix: extract one `<AppTabBar items active badge>` and use it in all three apps. Give parents the grouped More screen like admin.
- Bottom-bar labels at 10 px are too small. Use 11–12 px, as iOS uses 10 pt ≈ 13 px rendered.

**P1-3. Tables on mobile.**
- AdminClient's Students (`min-w-[620px]`), Coaches (`min-w-[500px]`) and Fees tables scroll sideways inside a card on a 390 px phone.
- Pagination links are `px-3 py-1 rounded` (about 28 px) and do a full page reload (`href="?page=…"`).
- Students has no search or filter and no empty state, even though `ui/data-filters.tsx` exists.
- Fix, following Stripe/Linear mobile: below `sm`, render rows as a list (name + batch on line 1, parent on line 2, fee pill on the right, chevron) and open the existing `StudentDetailDrawer`. Keep the table for `sm+`. Use client pagination or infinite scroll with 44 px controls.
- Same issue in `parent/FeeHistory.tsx`, `org/WaitlistManager.tsx` and `org/CouponManager.tsx`.

**P1-4. Touch targets under 44 px in core coach flows.**
- `SessionAttendanceCard.tsx`: secondary actions are `h-8` (lines ~384, 427, 435, 445, 659, 667) and avatars are `w-7 h-7`.
- Marketing language toggle: `px-3 py-1.5`, about 28 px. Header "Start free" is `h-9`.
- Receipt actions (`r/[token]` 78–88) are `py-1.5 text-xs`.
- Admin header links at `text-xs`.
- Coaches use these one-handed on the ground. Make `h-11` the floor for anything tappable on `pointer:coarse`.

**P1-5. Marketing doesn't follow the theme and has no mobile nav.**
- `marketing.css` hard-codes `rgba(163,230,53,…)` (lime) glow and a **white** dot grid. In the default light theme the grid is invisible and the glow is green against an orange brand.
- The hero headline (`hero-copy.tsx`) is `from-lime-300 via-lime-400 to-emerald-400` gradient text, which in light theme becomes a dark-orange→orange→green gradient.
- `shell.tsx:75` hides Features/Pricing/Academies/FAQ under `md` and there is no menu, so on phones Pricing and the directory are only reachable from the footer.
- The Hindi eyebrow says "गुड़गांव फाउंडिंग ऑफ़र" (Gurgaon founding offer) but the English one doesn't mention Gurgaon. The copy is out of sync.
- Fix: port marketing to semantic tokens, drop `mk-float`/`mk-glow`/`mk-ping`, and add a sheet menu at `<md`.

**P1-6. The always-on `.dark` class.** `layout.tsx` puts `className="dark"` on `<html>` even when `data-theme="light"`, so every shadcn `dark:` variant is active in light mode (for example the `button.tsx` outline variant uses `dark:bg-input/30 dark:border-input`). It works only because `.dark` re-maps vars to the neutral ramp. Make the class follow the theme (`.dark` only when `data-theme="dark"`), or delete the `dark:` variants from vendored components. Otherwise future shadcn adds will look wrong in light.

**P1-7. Ramp aliasing hazards.**
- `text-white` means "inverse ink", so in light it is near-black. Any `bg-emerald-600 text-white` or `bg-rose-600 text-white` renders dark text on a saturated fill (rose-600 with ink is 4.0:1).
- `emerald/amber/rose/sky-500…950` aren't in the ramp, so they fall back to raw Tailwind (534 uses), which means status colours differ between themes.
- In light, `n-300` (71 84 103) and `n-400` (75 85 101) are nearly identical, so `text-zinc-300` vs `text-zinc-400` hierarchy disappears.
- Fix: introduce `on-accent`/`on-success`/`on-danger` foregrounds and complete the status ramps (50, 500, 600 tints for fills).

**P1-8. Two `EmptyState`s.**
- `ui/empty-state.tsx` (📭 emoji, `text-zinc-600` description, 1 user) and `shell/EmptyState.tsx` (good, 5 users).
- Many panels have no empty state at all: the students table, `FeeHistory`, `CouponManager`, `TestimonialCollector`.
- Delete the old one and require `EmptyState` + action wherever a list can be empty.

**P1-9. Focus visibility is patchy.**
- 55 `focus:outline-none` + 34 `outline-none`, against only about 30 explicit `focus-visible:ring` declarations.
- `globals.css:175` gives inputs only a 3 px 18%-alpha brand shadow, which is faint on light.
- `dashboard-shell` NavButtons and bottom-bar buttons have no focus style.
- Fix: add one global rule, `:focus-visible { outline: 2px solid rgb(var(--c-accent)); outline-offset: 2px }`, and remove the ad-hoc `outline-none`.

**P1-10. Parent portal tone.** Gamification copy ("🔥 LEGENDARY STREAK", "Century Club 💎", "PTS", `font-black`) and stars rendered as text `★` with no `aria-label` (`FeedbackWidget.tsx:39,68`). These clash with the calm owner app and look templated. Keep the streak and progress (the Spond/TeamSnap parent value) but present it in the shell language. Rating input should be a radiogroup.

**P1-11. Brand mark is inconsistent.** The marketing header uses a "Triq" text logo (`marketing/shell.tsx:31`). Login uses `TriqWordmark`. Onboarding uses `uppercase italic font-black gradient-text "TRIQ"` (`onboarding/page.tsx:110`). The app shell uses a single-letter tile. The old coach header used "TRQ". Pick one wordmark plus one app-icon glyph.

**P1-12. Toasts.** `ThemedToaster` is `position="top-right"`. On phones it covers the sticky header and the SOS button. Use `bottom-center` with an offset above the 56–64 px tab bar on mobile, and top-right on desktop. Copy varies: "Child enrolled successfully!" vs "Order cancelled", and "Failed to…" vs "Could not…". Standardise on "Couldn't X. Try again." and past-tense success with no "!".

**P1-13. No `not-found.tsx`** at the app root, so 404s render Next's unstyled default. Also add `loading.tsx` for `/staff`, `/student/[id]`, `/academies/*` and `/book/[slug]`. Only org, coach and parent have one.

## 4. P2: polish

- Uppercase micro-labels everywhere: `TableHead` is `text-xs uppercase` in AdminClient, and `text-[10px]/[11px] font-bold uppercase tracking-wider` appears in about 60 places. Use sentence-case 12–13 px medium `text-ink-muted`, which reads calmer (Linear/Stripe do this).
- `StatusChip` and the receipt header use pulsing "live" dots (`r/[token]/page.tsx:99`) on static facts. Remove them. A receipt is not live.
- AdminClient header: "Pricing ↗ / Registration ↗ / Trial ↗" are text arrows at `text-xs zinc-500`. Move them to Settings → "Public links" with copy buttons. "Sign Out" takes header space on mobile; move it into More/Settings (as Linear does).
- `AdminClient.tsx` batch cards show a literal "Capacity: —" in `text-zinc-600`. Hide the line when it's unknown.
- `motion.ts` `stagger()` is a no-op kept for old callers, and `glass`, `gradient-text`, `bg-orbs` and `hover-lift` are legacy shims in `globals.css`. Delete them after migrating, along with unused `glow-card`, `stat-card`, `loading-button`, `animated-counter` and `paginated-table`, and the unused deps `framer-motion` and `canvas-confetti` (0 imports).
- `"use client"` is on files that don't need it: `ui/skeleton.tsx`, `ui/StatusChip.tsx`. There are 173 client `.tsx` files in total. `AdminClient` is one 824-line client tree typed `any`. Tab switching with `key={activeTab}` remounts the whole tab on each switch, so state is lost and work is repeated. Consider `hidden` panes like `CoachTabs` for the top 3 tabs.
- `page.tsx` metadata: the root title is "Triq | Sports Academy Platform" and the OG title uses an em dash. Unify title templates (`%s · Triq`).
- No `next/image` anywhere (13 raw `<img>`). Directory and gallery images should use `next/image` with `sizes` to save mobile data.
- Dates use 15 bare `toLocaleDateString()` calls plus `en-US`, `en` and `undefined` variants, so receipts and the student page show `10/26/2026` on some devices. Standardise on "26 Oct 2026" / "Sat, 26 Oct".
- `KpiTile` value drops to `text-[22px]` with `truncate` on phones. Long ₹ values ("₹1,25,000") get ellipsised. Use the compact format (₹1.25L) under `sm`.
- `data-theme` is stored per browser only (`theme.ts`). Respect `prefers-color-scheme` for first visit (the boot script currently defaults to light).

## 5. Proposed design-system cleanup

**Tokens** (`themes.css` + `tailwind.config.ts`)
1. Keep the semantic layer (`canvas`, `surface`, `surface-2`, `line`, `ink`, `ink-muted`, `ink-subtle`, `volt`, `success`, `warn`, `danger`). Add the following:
   - `line-strong` (hover border) and `ring` (focus).
   - `info` and `violet` (plus `on-*` foregrounds).
   - Tinted fills `success-soft`, `warn-soft`, `danger-soft`, `info-soft`, `accent-soft`, so `bg-emerald-500/10 border-emerald-500/30` stops being hand-written 534 times.
2. Freeze the legacy aliases. Add an ESLint rule (`eslint-plugin-tailwindcss` `no-custom-classname` allowlist, or a simple regex check in CI) that bans:
   - `text-zinc-(600|700|800|900)`;
   - any `purple|cyan|indigo|violet|blue|red|gray|pink|orange|yellow|teal|fuchsia-*`;
   - status shades outside the ramp;
   - `font-black`;
   - `text-[Npx]`.
   Then migrate `zinc-*` to semantic tokens file by file, starting with `parent/*` and `ui/*`.
3. **Type scale** (replace about 345 arbitrary sizes): `text-2xs` 11/14 (tab labels only), `text-xs` 12/16, `text-sm` 13/18 (app body), `text-base` 15/22, `text-lg` 17/24, `text-xl` 20/28, `text-2xl` 24/30, `text-display` 32/36 (KPI). Weights: 400/500/600 only, with 700 for the marketing H1.
4. **Radius**: `sm` 6 (chips, inputs inside groups), `md` 8 (buttons, inputs), `lg` 12 (cards, sheets), `full` (avatars, pills). Retire `2xl`/`3xl` in the app (keep them for marketing only if wanted).
5. **Elevation**: `shadow-hairline` for cards and one `shadow-pop` for popovers/sheets. Retire `shadow-xl`/`2xl` and glows.
6. **Spacing rhythm**: 4-pt grid. Page gutter 16/32. Section gap 32 (`space-y-8`). Card padding 16/20. List row min-height 56.
7. **Motion**: already well defined in `motion.ts`/globals. Move marketing onto the same `--dur-*`/`--ease-*` and drop infinite loops (float, ping, pulse).

**Components to standardise** (single source each, in `src/components/ui`)
- `Button` (primary/secondary/ghost/danger; sizes sm 36 / md 40 / lg 48; coarse-pointer min 44). Replace `shellButton`, `AthleticButton` and ad-hoc `<button className="h-8 …">`.
- `Input`, `Select`, `Textarea`, and `Field` (label + hint + error with `aria-describedby`/`aria-invalid`, set automatically). Only 8 files use `aria-invalid`/`aria-describedby` today.
- `Card`, `ListRow` (avatar · title · meta · trailing · chevron) and `ResponsiveTable` (table ≥sm, `ListRow` <sm).
- `Badge`/`StatusPill` (paid, due, overdue, pending-verification, present, absent, trial, at-risk), one map in `lib/status.ts` used by admin, coach and parent.
- `EmptyState` (shell version), `Skeleton` set (`PanelSkeleton` already good), `ConfirmDialog` + `useConfirm()`, `Sheet` (vaul, already a dependency) for mobile forms instead of centred dialogs.
- `AppTabBar` + `AppHeader` shared by admin, coach and parent.
- `Money`, `DateText` and `Num` components wrapping `lib/format.ts`.
- `KpiTile` (exists, use it in the parent and coach apps too).

## 6. Benchmarks: what to copy concretely

- **Linear.** One 13 px body size with sentence-case labels and muted secondary text. Every list row is the same `ListRow`. Cmd-K exists (`ui/command-palette.tsx`), so surface it with a visible "Search ⌘K" field in the desktop sidebar header. Keyboard focus is always visible.
- **Stripe Dashboard.** Money is always locale-formatted with the currency and right-aligned tabular numbers. Status pills say "Succeeded / Pending / Failed" with a small dot, sentence case. Below `md`, tables collapse to list rows. Each list has filter chips (status, batch, month) above it. Receipts are print-first, with no live dots.
- **Notion.** Empty states are one line plus one primary action, without illustration (the shell `EmptyState` already does this; make it universal).
- **Playtomic.** For Bookings/Turf (`BookClient.tsx`, `TurfBoard.tsx`): a horizontal day strip with 44 px day pills, a time-slot grid with large tappable slots, price on the slot, and a sticky bottom CTA showing the total.
- **TeamSnap / Spond.** For the parent app: an event card with a one-tap "Going / Not going" RSVP (`RSVPButtons` exists, so put it on Home), an availability count on the coach side, and a single feed of announcements plus attendance plus payments rather than separate widgets. Spond's payment request card (amount, due date, Pay button, paid state with a check) is the model for `CheckoutModal`/`FamilyDashboard`.
- **Coach attendance** (Spond/TeamSnap): full-width rows with a 44 px present/absent toggle on the right, "Mark all present" sticky at the bottom, and undo in the toast. `SessionAttendanceCard` has the pieces but the secondary actions are 32 px and there are too many uppercase micro-labels.

## 7. The 10 changes that would most raise perceived quality

1. **Restyle the five base primitives** (`ui/card.tsx`, `ui/badge.tsx`, `ui/button.tsx`, `ui/input.tsx`, `ui/StatusChip.tsx`) to the shell language: `rounded-xl` hairline cards, sentence-case 12 px badges with no pulse, 40/44 px buttons. This changes about 100 files at once.
2. **Kill unreadable colour.** Replace `text-zinc-600/700/800` with `text-ink-subtle`, and map purple/cyan/indigo/red/blue to themed `info`/`violet`/`danger`. Add a lint rule so they don't return.
